# 회사 맞춤 앱에서 출시 앱으로 전환

현재 전용 앱은 승인된 메뉴 디자인과 로그인·차량·일정 조회 단계이며 업무용 배포 앱을 대체할 수 없다. 배차/회수 편집, 메신저/AI, 알림, 두 위젯, 위치 공유, 관리자가 쓰는 기능 이전은 미완료다. 메뉴에서 준비 중인 기능은 안내창을 표시한다.

## 업체 분리

- 소속은 Firebase Auth UID → userIndex → 회사 members의 서버 검증으로 결정한다. 회사명을 보고 업체를 선택하거나 회사 id를 상수로 지정하지 않는다.
- 캐시는 UID+회사별 분리, AndroidKeyStore AES-GCM 암호화, 백업 제외. 로그아웃/권한 해제 시 제거한다. 서버에서 권한을 확인하지 못하면 시작 단계에서 캐시를 노출하지 않는다.
- 기본 지점/장기 구분/회사 표시명은 profile에서 읽는다. 없는 값은 기존 차량 지점에서 추론하되 데이터베이스에 자동 저장하지 않는다. 향후 회사 설정 스키마를 실제 웹과 일치시킬 필요가 있다.
- Firebase 보안 규칙이 데이터 접근을 최종 결정한다. 클라이언트 역할 확인만으로 권한이 보장됐다고 판단하지 않는다. 출시 전 규칙 테스트/Emulator가 필요하다.

## 출시 전 통과 조건

1. 기존 앱 기능별 동작 비교: 차량 순서, 지점, 회수 경고, A/S/보험/검사/차령 경고, 배차 재출고 건수, 일반/보험/장기, 사진/상대 차량 메모, 금액, 계약서/변경 기록, 직원 권한.
2. 실제 기기: 낮은 사양 포함 최초 실행/재실행, 긴 목록, 사진 여러 장, 앱 재개, 화면 회전, 프로세스 종료, 통신 끊김, 업체 변경 및 퇴사자 접근.
3. 기존 앱 서명/패키지 및 widget provider 이름 호환, FCM token 이전, 알림 중복 방지, 일정 날짜 링크 및 홈 팝업, 캐시 이전/삭제.
4. 개인정보 처리방침 및 동의, 계정/회사 데이터 삭제 흐름, 보유 기간, 사진/GPS 목적과 수집 범위, 관리자 권한, 권한 철회, 휴일/업무 종료 처리. 현재 시험판은 위치를 수집하지 않는다.
5. Play 등록 때 최신 target SDK 및 백그라운드 위치/사진 접근/알림 정책을 공식 문서로 재확인. 지금의 target 35 빌드 설정을 출시 기준으로 단정하지 않는다.
6. 스토어 배포용 서명/업로드키를 비공개로 보관, 테스트와 운영 환경 분리, AAB, 내부 테스트/점진 배포, 오류 대응 및 롤백 계획.
7. AI 서비스 키는 출시 전에 서버에서 보관/호출하도록 전환, 고객사별 사용량/오류/비용 제한 마련. 서비스 계정/관리자 키는 APK 또는 공개 저장소에 넣지 않는다.

## 아직 필요한 사용자 결정

- 위치 동의 화면 제외 휴일: 토·일+공휴일 / 일+공휴일 / 직원별 휴무일.
- 이미 동의한 직원도 매일 첫 실행 때 재동의하는지.
- 직원/관리자 메뉴 화면은 2026-10-03 새 시안으로 승인됐다.
- 출시 앱에 포함할 계약서·수납 기능 범위, 가격/가입 정책은 향후 별도 결정.
